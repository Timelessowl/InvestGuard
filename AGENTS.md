# InvestGuard — правила для ИИ-агентов и разработчиков

Этот файл читают ИИ-агенты (Claude Code подключает его через `CLAUDE.md`) и люди. Правила действуют для любой задачи в репозитории.

## Контекст проекта

InvestGuard (в интерфейсе — «ИнвестСигнал») разрабатывается для Министерства экономики Свердловской области. Сервис заранее находит компании, которые, возможно, планируют:

- открыть новое предприятие;
- построить производственный объект;
- расширить действующее производство;
- модернизировать производственные мощности;
- выйти на территорию Свердловской области;
- создать новые рабочие места.

Дополнительная задача — найти компании, которые уже проявляют инвестиционную активность, но упираются в препятствия: нет земельного участка, не хватает электрической мощности, проблемы с подключением коммуникаций, административные ограничения и другое.

Министерство должно узнавать о таких компаниях до их официального обращения за господдержкой.

Основной проект — каталог `invest-guards-promo`.

## Что уже есть

- Backend на Python / FastAPI, PostgreSQL, Docker Compose.
- Frontend на React / TypeScript.
- Сбор RSS-лент и публикаций Яндекс Дзена.
- ИИ-анализ новостей через GigaChat и карточки инвестиционных кандидатов.
- Объединение повторяющихся новостей и доказательств.
- Проверка компаний через Контур.Фокус API3, скоринг кандидатов и финансовых рисков.
- ИИ-ассистент с инструментами для карточек и источников.
- Карта инвестиционных проектов, экспорт одобренных карточек в CSV.

## Общие требования к разработке

- Не переписывай проект с нуля. Не удаляй и не ломай существующие функции.
- Сохраняй обратную совместимость существующих API, карточек и демонстрационных данных.
- Не дублируй уже существующую интеграцию с Контур.Фокусом.
- Каждую новую интеграцию делай отдельным адаптером источника.
- Не помещай API-ключи и секреты в код, frontend или Git. Репозиторий публичный.
- Новые настройки добавляй в `.env.example`; реальные значения — только в переменных окружения.
- Используй существующую архитектуру: PostgreSQL, SQLAlchemy, FastAPI, React.
- Изменения структуры БД оформляй отдельными SQL-миграциями `backend/migrations/NNN_name.sql`; они применяются по порядку при старте.
- Для каждой новой функции добавляй автоматические тесты.
- Внешние API в тестах — только через mock-транспорт. Тесты не делают реальных платных запросов.
- Соблюдай ограничения API, правила использования источников и условия обработки данных.
- Не используй неофициальный скрейпинг, обход CAPTCHA и закрытые данные без согласованного доступа.
- Если публичного API нет или доступ не подтверждён, не имитируй работающую интеграцию: зафиксируй ограничение и резервный способ загрузки данных.
- Не создавай фиктивные инвестиционные сигналы в рабочих данных.
- Если данных недостаточно, сохраняй неопределённость, а не придумывай значения.

## После каждой задачи

1. Запусти нужные тесты и проверь, что нет регрессий.
2. Покажи список изменённых файлов.
3. Объясни, что реализовано.
4. Укажи оставшиеся ограничения и необходимые настройки.


## Git

- Одна задача — одна ветка `feature/<кратко>`. В `main` и `develop` напрямую не коммитим.
- Сообщения коммитов короткие, с префиксом `f:` (функциональность) или `b:` (исправления, инфраструктура, документация). Без email-адресов и служебных подписей.
- `.env`, ключи и выгрузки данных не коммитим.
- PR и слияние веток — только по решению команды.
