# ИнвестСигнал — пилот

React-приложение с Python/FastAPI API и PostgreSQL. Система сама собирает новости из открытых источников, отбирает сигналы об инвестиционных проектах Свердловской области с помощью GigaChat, оценивает их и складывает в очередь аналитика. Встроенный ассистент работает с теми же данными через инструменты: ищет карточки, меняет статусы по просьбе, запускает сбор и разбор.

Шесть демонстрационных карточек из первой версии остаются в базе с меткой «Демо». Карточки из пайплайна помечены «ИИ». Авторизации пока нет.

## Запуск

Из этой папки:

```sh
cp .env.example .env   # впишите LLM_BASE_URL и LLM_API_KEY
docker compose up -d --build --wait
```

Откройте http://localhost:18473. Стек из четырёх контейнеров:

| Сервис | Назначение |
| --- | --- |
| `frontend` | React/Nginx; обслуживает UI и проксирует `/api` |
| `backend` | Python 3.12 / FastAPI; API, чат-ассистент |
| `worker` | Тот же образ, `python -m app.worker`: сбор по расписанию и разбор документов |
| `db` | PostgreSQL 17; данные в томе `postgres_data` |

Наружу опубликован только порт frontend. Порт меняется через `APP_PORT`. Без `LLM_API_KEY` воркер только собирает документы, а чат и разбор отвечают «ИИ не настроен».

Пароль БД по умолчанию предназначен для демо. Файл `.env` не отслеживается Git — ключ ИИ храните только там.

## Пайплайн

```
RSS-ленты ──► documents (new)
  1. префильтр: ≥2 разных «инвестиционных» корня; для нерегиональных лент — упоминание области/муниципалитета
  2. эмбеддинг EmbeddingsGigaR; косинус ≥ 0.93 с уже разобранным документом → повтор, приклеивается к той же карточке без LLM
  3. триаж GigaChat-3-Pro (JSON Schema): сигнал ли это, компания, муниципалитет, цитата, уверенность
  4. компания уже есть в очереди → документ добавляется доказательством, растёт «Уверенность»
  5. иначе GigaChat-3-Pro готовит карточку: резюме, сумма, стадия, факторы 0–100, рекомендация
```

Итоговая оценка считается в коде: 0.35·Релевантность + 0.25·Уверенность + 0.2·Региональный эффект + 0.2·Срочность. Координаты берутся из справочника центров муниципалитетов (`backend/app/geo.py`), поэтому точность — муниципалитет.

Этапы документа: `new` → `skipped` (фильтр), `rejected` (ИИ), `signal` (новая карточка), `merged` (добавлен к карточке), `error` (три неудачные попытки). Вся лента видна на странице «Источники».

Источники описаны в `backend/seed/sources.json` и синхронизируются с БД при каждом старте; время последнего запуска и ошибка сохраняются. Ленты скачиваются напрямую (`trust_env=False`) с честным User-Agent. Сертификат Минцифры лежит в `backend/certs`, он нужен части региональных сайтов. Дополнительные CA можно передать через `EXTRA_CA_FILE`.

### Бюджет ИИ

Каждый вызов пишется в `llm_usage` с токенами и стоимостью (заголовок `x-litellm-response-cost`, иначе — по таблице цен в `app/llm.py`). При достижении `LLM_BUDGET_USD` или `LLM_DAILY_BUDGET_USD` разбор останавливается, документы остаются в очереди, API отвечает 429. Первый прогон на 451 документе стоил около $0.10: префильтр отсекает ~97% документов.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | — | OpenAI-совместимый эндпоинт LiteLLM |
| `LLM_TRIAGE_MODEL` | `GigaChat-3-Pro` | Триаж документа; Lightning дешевле, но заметно чаще ошибается |
| `LLM_SMART_MODEL` | `GigaChat-3-Pro` | Карточки и чат |
| `LLM_EMBED_MODEL` | `EmbeddingsGigaR` | Поиск повторов |
| `LLM_BUDGET_USD` / `LLM_DAILY_BUDGET_USD` | `45` / `3` | Общий и дневной лимит |
| `PIPELINE_INTERVAL_SECONDS` / `PIPELINE_BATCH` | `60` / `20` | Такт воркера и сколько документов он разбирает за такт |
| `PIPELINE_WORKER` | — | `1` запускает воркер внутри API-процесса (удобно локально) |

### Ассистент

`POST /api/chat` получает историю диалога и крутит цикл tool calling (до 6 шагов) на GigaChat-3-Pro. Инструменты: `search_candidates`, `get_candidate`, `update_candidate`, `create_signal`, `search_documents`, `pipeline_status`, `collect_sources`, `process_documents` (не больше 10 документов за раз). Ответ содержит трассировку вызовов, а UI показывает, что ассистент сделал. Тексты новостей передаются модели как данные; менять карточки она должна только по явной просьбе пользователя.

## API

Документация: http://localhost:18473/api/docs.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/state` | Карточки, источники, пример аналитики и статистика пайплайна |
| GET/POST | `/api/candidates` | Список / ручной сигнал |
| GET/PATCH | `/api/candidates/{id}` | Карточка / status, owner, nextAction; статус экспортированной не меняется (409) |
| GET | `/api/sources` | Источники с числом документов и сигналов |
| POST | `/api/sources/{id}/collect` | Скачать ленту сейчас |
| GET | `/api/documents?stage=&source=&q=` | Собранные документы и решение по каждому |
| POST | `/api/pipeline/process` | Разобрать до `limit` (≤30) новых документов сейчас |
| GET | `/api/llm/usage` | Расход и лимиты |
| POST | `/api/chat` | Ассистент |
| POST | `/api/exports`, GET `/api/exports/{id}` | CSV одобренных карточек |
| GET | `/api/health` | Готовность API/БД |

## Разработка и проверки

Без Docker: PostgreSQL 14+, Python 3.11–3.12, Node 22+.

```sh
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-test.txt
set -a && . ../.env && set +a
PGHOST=127.0.0.1 PGUSER=postgres PGPASSWORD= PGDATABASE=investsignal PIPELINE_WORKER=1 \
  .venv/bin/uvicorn app.main:app --port 18000
```

```sh
cd frontend
npm ci
API_PROXY_TARGET=http://127.0.0.1:18000 npm run dev
```

Проверки:

```sh
cd frontend && npm run typecheck && npm test && npm run build
cd backend && PGHOST=127.0.0.1 PGUSER=postgres PGDATABASE=postgres .venv/bin/python -m pytest -q
```

Бэкенд-тесты создают и удаляют временные базы. LLM и RSS в них подменены через `httpx.MockTransport`, поэтому тесты не тратят бюджет. Проверяются сбор, префильтр, склейка повторов, карточка, бюджет, цикл инструментов чата, а также сохранение данных, конкурентные изменения, валидация и экспорт. В Compose:

```sh
docker compose run --rm --no-deps --user root backend sh -c 'pip install --no-cache-dir -r requirements-test.txt && python -m pytest -q'
```

## Сервер и HTTPS

Конфигурация обслуживает HTTP на внутреннем порту 8080. TLS-прокси сервера должен направлять запросы к frontend, включая `/api`. На x86-64 сервере собирайте образы там же или для `linux/amd64`.

Старый статический Dockerfile в корне сохранён как артефакт промо; основной `compose.yaml` использует `frontend/Dockerfile`.
