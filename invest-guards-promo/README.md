# ИнвестСигнал — пилот

React-приложение с Python/FastAPI API и PostgreSQL. Система сама собирает новости из 19 открытых источников (региональные, федеральные и отраслевые СМИ, Яндекс Дзен), отбирает сигналы об инвестиционных проектах Свердловской области с помощью GigaChat, оценивает их и складывает в очередь аналитика. Инициатора проекта можно проверить по ИНН в Контур.Фокусе: банкротство, суды, приставы, блокировки счетов, достоверность ЕГРЮЛ и владельцы сводятся в зелёный, жёлтый или красный вердикт. Встроенный ассистент работает с теми же данными через инструменты: ищет карточки, меняет статусы по просьбе, запускает сбор и разбор, проверяет компании.

Шесть демонстрационных карточек из первой версии остаются в базе с меткой «Демо». Карточки из пайплайна помечены «ИИ». Доступ закрыт HTTP Basic Auth для одного пользователя; регистрации нет.

## Запуск

Из этой папки:

```sh
cp .env.example .env   # впишите AUTH_PASSWORD, LLM_BASE_URL и LLM_API_KEY
docker compose up -d --build --wait
```

Откройте http://localhost:18473. Стек из четырёх контейнеров:

| Сервис | Назначение |
| --- | --- |
| `frontend` | React/Nginx; обслуживает UI и проксирует `/api` |
| `backend` | Python 3.12 / FastAPI; API, чат-ассистент |
| `worker` | Тот же образ, `python -m app.worker`: сбор RSS по расписанию и разбор документов |
| `db` | PostgreSQL 17; данные в томе `postgres_data` |
| `dzen` | По желанию: сбор Дзена в headless-браузере, образ `backend/Dockerfile.dzen` на базе Playwright. Включается так: `docker compose --profile dzen up -d --build` |

Наружу опубликован только порт frontend. Порт меняется через `APP_PORT`. Без `LLM_API_KEY` воркер только собирает документы, а чат и разбор отвечают «ИИ не настроен». Без `FOCUS_API_KEY` блок проверки инициатора сообщает, что Контур.Фокус не настроен.

Пароль БД по умолчанию предназначен для демо. Файл `.env` не отслеживается Git — ключ ИИ храните только там.

### Вход

В `.env` задайте `AUTH_USERNAME=poc_user` и `AUTH_PASSWORD` — длинный уникальный пароль из ASCII-символов. Имя пользователя можно изменить (ASCII, без двоеточий); пароль может содержать двоеточия. Без `AUTH_USERNAME` используется `poc_user`. Без непустого `AUTH_PASSWORD` API не запускается. Секреты читаются только бэкендом при запуске и не включаются в сборку браузера.

При открытии сайта браузер покажет стандартное окно входа. Используются встроенные механизмы FastAPI HTTPBasic и Nginx auth_request: Nginx проверяет доступ к HTML и ресурсам через API, а API проверяет каждый запрос самостоятельно, включая чат, запуск разбора и документацию. Регистрации и дополнительных аккаунтов нет. Для скриптов используйте HTTP Basic Auth. Без входа доступны только `/healthz` и `/api/health` для проверки работоспособности.

На публичном сервере используйте HTTPS на внешнем TLS-прокси: HTTP Basic передаёт учётные данные с каждым запросом. После смены учётных данных пересоздайте API (`docker compose up -d --wait backend`); браузер запросит новый пароль. Воркер продолжает сбор и разбор по расписанию в пределах бюджета независимо от входа пользователя.

Деплой на сервер, заполнение секретов, обновление существующей установки и резервная копия БД: **[DEPLOYMENT.md](DEPLOYMENT.md)**. Все настройки из `.env.example`, включая модели, бюджет и расписание воркера, передаются API и воркеру. После правки `.env` контейнеры нужно пересоздать через `docker compose up -d --wait`; `restart` не подхватывает новые значения.

## Пайплайн

```
RSS-ленты, поиск Дзена ──► documents (new)
  1. префильтр без ИИ: кликбейт-заголовки (для Дзена порог строже); ≥2 разных «инвестиционных» корня;
     для нерегиональных лент — упоминание области/муниципалитета
  2. эмбеддинг EmbeddingsGigaR; косинус ≥ 0.93 с уже разобранным документом → повтор, приклеивается к той же карточке без LLM
  3. триаж GigaChat-3-Pro (JSON Schema): сигнал ли это, компания, муниципалитет, цитата, уверенность
  4. компания уже есть в очереди → документ добавляется доказательством, растёт «Уверенность»
  5. иначе GigaChat-3-Pro готовит карточку: резюме, сумма, стадия, факторы 0–100, рекомендация
```

Итоговая оценка считается в коде: 0.35·Релевантность + 0.25·Уверенность + 0.2·Региональный эффект + 0.2·Срочность. Координаты берутся из справочника центров муниципалитетов (`backend/app/geo.py`), поэтому точность — муниципалитет.

Этапы документа: `new` → `skipped` (фильтр), `rejected` (ИИ), `signal` (новая карточка), `merged` (добавлен к карточке), `error` (три неудачные попытки). Если GigaChat отвечает шаблонным отказом (фильтр «чувствительных тем») вместо JSON, документ сразу получает `rejected` с текстом отказа, без повторов. Вся лента видна на странице «Источники».

Если в тексте новости или в ответе модели есть ИНН компании (с верной контрольной суммой), он сохраняется в карточке, и при `FOCUS_AUTO_CHECK=1` инициатор сразу проверяется в Контур.Фокусе.

### Источники

| Группа | Источники |
| --- | --- |
| Региональные и городские СМИ | Областная газета, JustMedia, 66.ru, E1.ru, Вечерние ведомости, АиФ-Урал |
| СМИ УрФО и деловые | URA.news, Уралинформбюро, Коммерсантъ-Урал |
| Федеральные СМИ | РБК, Интерфакс, Ведомости, РИА Новости, Российская газета, Коммерсантъ · Экономика |
| Отраслевые порталы | Стройгазета, Агроинвестор, CNews |
| Яндекс Дзен | поиск по запросам из `sources.json` («завод Свердловская область», «инвестиционный проект Свердловская область» и др.) |

Федеральные и окружные ленты помечены `regional: false`: документ проходит дальше, только если в нём упомянута область или её муниципалитет. Битая запись в ленте не роняет всю ленту: при ошибке XML записи разбираются по одной.

У Дзена нет RSS и публичного API, а страницы отрисовываются скриптом. Поэтому сервис `dzen` открывает поиск Дзена в headless-браузере, как обычный читатель, и забирает ссылки, заголовки и анонсы публикаций. Если Дзен показывает капчу, сбор останавливается с ошибкой источника; обходить её мы не пытаемся. Локально без Docker: `pip install -r requirements-dzen.txt` и `DZEN_BROWSER_CHANNEL=chrome` (системный Chrome); воркер собирает Дзен, если в `SOURCE_KINDS` есть `dzen`.

Фильтр кликбейта (`app/clickbait.py`) взвешивает признаки заголовка: интрига вместо факта («вы не поверите», «шок», «вот почему»), обращение к читателю, «уникальный завод, который может увидеть каждый», списки «5 причин», вводные «во-первых», капслок, эмодзи и «!!». Для Дзена документ отсеивается при сумме ≥2, для СМИ — при ≥3. Причина видна в ленте документов.

Источники описаны в `backend/seed/sources.json` и синхронизируются с БД при каждом старте; время последнего запуска и ошибка сохраняются. Ленты скачиваются напрямую (`trust_env=False`) с честным User-Agent. Сертификат Минцифры лежит в `backend/certs`, он нужен части региональных сайтов. Дополнительный CA положите на сервере в `certs/company-ca.pem`, а в `.env` задайте `EXTRA_CA_FILE=/run/investsignal/certs/company-ca.pem`: каталог монтируется в API и воркер только для чтения и игнорируется Git.

### Бюджет ИИ

Каждый вызов пишется в `llm_usage` с токенами и стоимостью (заголовок `x-litellm-response-cost`, иначе — по таблице цен в `app/llm.py`). При достижении `LLM_BUDGET_USD` или `LLM_DAILY_BUDGET_USD` разбор останавливается, документы остаются в очереди, API отвечает 429. Первый прогон на 451 документе стоил около $0.10: префильтр отсекает ~97% документов.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | — | OpenAI-совместимый эндпоинт LiteLLM |
| `LLM_TRIAGE_MODEL` | `GigaChat-3-Pro` | Триаж документа; Lightning дешевле, но заметно чаще ошибается |
| `LLM_SMART_MODEL` | `GigaChat-3-Pro` | Карточки и чат |
| `LLM_EMBED_MODEL` | `EmbeddingsGigaR` | Поиск повторов |
| `LLM_BUDGET_USD` / `LLM_DAILY_BUDGET_USD` | `45` / `3` | Общий и дневной лимит |
| `PIPELINE_INTERVAL_SECONDS` / `PIPELINE_BATCH` | `60` / `20` | Такт воркера и сколько документов он разбирает за такт |
| `PIPELINE_WORKER` | — | `1` запускает воркер внутри API-процесса (удобно локально) |
| `SOURCE_KINDS` | `rss` | Какие источники собирает этот процесс: `rss`, `dzen` или оба через запятую |
| `PIPELINE_PROCESS` | `1` | `0` — только сбор без разбора (так работает сервис `dzen`) |
| `DZEN_BROWSER_CHANNEL` | — | `chrome` — использовать системный Chrome вместо браузера Playwright |
| `FOCUS_API_KEY` | — | Ключ Контур.Фокус API |
| `FOCUS_INN_LIMIT` | `950` | Сколько разных ИНН система вправе проверить (запас от лимита ключа в 1000) |
| `FOCUS_AUTO_CHECK` | `1` | Проверять инициатора сразу, если ИНН найден в тексте новости |
| `FOCUS_TTL_DAYS` | `30` | Сколько дней результат проверки берётся из кеша |

### Проверка инициатора: Контур.Фокус

Проверка запускается кнопкой в карточке (поле «ИНН компании-инициатора»), через ассистента («проверь INV-1018, ИНН …») или автоматически, если ИНН есть в тексте. По ИНН вызываются десять методов API3:

| Что проверяем | Методы Фокуса |
| --- | --- |
| Статус, регистрация, реквизиты | `req` |
| Финансовая устойчивость, налоги, экспертный рейтинг отчётности | `financeAnalytics` |
| Банкротство: процедуры, сообщения, намерения кредиторов | `bankruptcyAnalytics` |
| Арбитраж: иски к компании, проигранные дела, налоговые споры | `courtAnalytics` |
| Исполнительные производства, в том числе по зарплате | `fsspAnalytics` |
| Блокировки счетов ФНС | `fnsBlockedBankAccounts`, `legalAnalytics` |
| Недостоверность ЕГРЮЛ, дисквалификация, заявления о ликвидации и сменах | `legalAnalytics` |
| Аффилированность: массовый адрес и руководитель, связанные банкроты | `linkAnalytics` |
| Конечные бенефициары, уставный капитал | `beneficialOwners` |
| Собственные рейтинги Фокуса | `scoring` |

Методов `/arbitr`, `/fssp`, `/gpd`, `/relationships` из постановки в API3 нет, их роль выполняют аналитические методы из таблицы. Поиск по названию (`suggest`) в тариф ключа не входит, поэтому ИНН вводит аналитик или он находится в тексте.

**Лимит.** Ключ даёт 1000 компаний на каждый метод до 31.01.2027, повторные запросы по той же компании лимит не тратят. Ответы хранятся в таблице `focus_checks`; новая компания проверяется, только пока их меньше `FOCUS_INN_LIMIT`. Неверная контрольная сумма ИНН отсекается до обращения к API. Остаток лимита виден на странице «Источники» и в блоке проверки.

**Флаги и вердикт** (`app/risk.py`). Вердикт определяется худшим флагом: есть красный — красная зона, иначе есть жёлтый — жёлтая, иначе зелёная. Пороги по судам и приставам считаются от выручки, поэтому 2,5 млн ₽ долгов для компании с выручкой 11 млрд — жёлтый флаг, а не красный.

| Уровень | Флаги |
| --- | --- |
| Красный (стоп-фактор) | недействующая, ликвидация или банкротство по ЕГРЮЛ; заявление о ликвидации; процедура или сообщения о банкротстве; дела о банкротстве против компании; недостоверные сведения ЕГРЮЛ; дисквалифицированный руководитель; блокировка счетов ФНС; высокий риск по «Знай своего клиента»; не сдаёт налоговую отчётность больше года; отрицательные чистые активы; слабый экспертный рейтинг (CCC и ниже); иски к компании ≥25% выручки; долги по зарплате у приставов; долги у приставов ≥ max(1 млн ₽, 1% выручки); низкий рейтинг благонадёжности Фокуса |
| Жёлтый (нужна проверка) | реорганизация; компания моложе года; намерение кредиторов банкротить; банкротство руководителя или учредителя; налоговый долг; Фокус рекомендует доппроверку; смена руководителя, владельцев или адреса за месяц; нет отчётности за последний год; убыток; падение выручки >30%; иски 5–25% выручки; налоговые споры ≥1 млн ₽; небольшие долги у приставов; ≥5 связанных компаний ликвидированы через банкротство; массовый адрес или руководитель (≥10 компаний); иностранные конечные владельцы; минимальный уставный капитал; средний рейтинг благонадёжности или низкие другие рейтинги Фокуса |
| Зелёный (плюс к надёжности) | работает больше 5 лет; крупная прибыльная компания (выручка ≥1 млрд ₽); сильный экспертный рейтинг; нет исполнительных производств; нет блокировок счетов; известен конечный владелец |

Пример на реальных данных: АО «ЕЗ ОЦМ» получает жёлтую зону — нет отчётности после 2021 года и 28 связанных компаний ликвидированы через банкротство, при этом нет долгов у приставов и блокировок, выручка 11 млрд ₽, известен владелец.

Результат сохраняется в карточке (`inn`, `risk`), попадает в CSV-выгрузку (колонки «ИНН» и «Риск (Контур.Фокус)») и показывается точкой рядом с ID в очереди.

### Ассистент

`POST /api/chat` получает историю диалога и крутит цикл tool calling (до 6 шагов) на GigaChat-3-Pro. Инструменты: `search_candidates`, `get_candidate`, `update_candidate`, `create_signal`, `search_documents`, `pipeline_status`, `collect_sources`, `process_documents` (не больше 10 документов за раз), `check_company` (проверка инициатора в Контур.Фокусе; тратит лимит, поэтому вызывается только по просьбе пользователя). Ответ содержит трассировку вызовов, а UI показывает, что ассистент сделал. Тексты новостей передаются модели как данные; менять карточки она должна только по явной просьбе пользователя.

## Разработка и проверки

Без Docker: PostgreSQL 14+, Python 3.11–3.12, Node 22+.

```sh
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-test.txt
set -a && . ../.env && set +a
PGHOST=127.0.0.1 PGUSER=postgres PGPASSWORD= PGDATABASE=investsignal PIPELINE_WORKER=1 \
  .venv/bin/uvicorn app.main:app --port 18000
```

```sh
cd frontend
npm ci
API_PROXY_TARGET=http://127.0.0.1:18000 npm run dev
```

Проверки:

```sh
cd frontend && npm run typecheck && npm test && npm run build
cd backend && PGHOST=127.0.0.1 PGUSER=postgres PGDATABASE=postgres .venv/bin/python -m pytest -q
```

Бэкенд-тесты создают и удаляют временные базы. LLM и RSS в них подменены через `httpx.MockTransport`, поэтому тесты не тратят бюджет. Контур.Фокус и браузер Дзена тоже подменены; фикстура Фокуса — урезанный реальный ответ без персональных данных. Проверяются сбор, разбор битых лент, кликбейт, Дзен, префильтр, склейка повторов, карточка, отказы GigaChat, бюджет, цикл инструментов чата, скоринг рисков, кеш и лимит Фокуса, а также сохранение данных, конкурентные изменения, валидация и экспорт. В Compose:

```sh
docker compose run --rm --no-deps --user root backend sh -c 'pip install --no-cache-dir -r requirements-test.txt && python -m pytest -q'
```

## Сервер и HTTPS

Конфигурация обслуживает HTTP на внутреннем порту 8080. TLS-прокси сервера должен направлять запросы к frontend, включая `/api`. Если прокси работает на самом сервере, задайте `APP_BIND=127.0.0.1`: приложение будет доступно через прокси и локально. По умолчанию `APP_BIND=0.0.0.0`, `APP_PORT=18473`. На x86-64 сервере собирайте образы там же или для `linux/amd64`.

Старый статический Dockerfile в корне сохранён как артефакт промо; основной `compose.yaml` использует `frontend/Dockerfile`.
